# 8. UX: esperienza d'uso per principianti

L'utente principale **non è un musicista**: l'app deve far ottenere un risultato piacevole in pochi minuti
(modello GarageBand / BandLab), lasciando le opzioni avanzate a dopo.

---

## 8.1 Trasporto e metronomo — `MVP`, difficoltà bassa

- Barra in alto: Play/Stop (**Spazio**), torna all'inizio, loop on/off, BPM modificabile (anche "tap tempo"
  = batti il tempo con un tasto, `v2`), posizione attuale (battuta.quarto), Rec (`v2`).
- **Metronomo:** "click" a ogni quarto, più forte sul primo della battuta (aiuta a capire dove inizia la battuta).
  Tone.js: `transport.scheduleRepeat((time) => click.triggerAttackRelease(nota, "32n", time), "4n")` con un
  `Tone.Synth`/`Tone.MembraneSynth` breve; accento leggendo la posizione in battuta. Canale separato dal
  master del brano (non deve finire nell'export).
- **Count-in** (1 battuta di conteggio prima della registrazione) — `v2`.

## 8.2 Tastiera virtuale suonabile col PC — `MVP`, difficoltà bassa

**Cos'è:** usare la tastiera del computer come un piccolo pianoforte. Schema standard di GarageBand
("Musical Typing", ripreso da Ableton e BandLab):
- riga centrale **A S D F G H J K L** = tasti bianchi (Do Re Mi Fa Sol La Si Do…);
- riga sopra **W E · T Y U · O P** = tasti neri (diesis/bemolle);
- **Z / X** = ottava giù / su; (in GarageBand **C / V** = velocity giù/su).
Più una tastiera di pianoforte cliccabile a schermo.

Implementazione: `keydown`/`keyup` → `synth.triggerAttack(nota)` / `triggerRelease(nota)`; ignorare
`event.repeat` (l'autorepeat del sistema rifarebbe partire la nota); usare `event.code` (posizione fisica:
funziona anche su tastiere italiane/AZERTY) e non `event.key`. Disattivarla quando il focus è in un campo di testo.
Conflitto con le scorciatoie: tenere la tastiera musicale attivabile (tasto dedicato, es. Ctrl+K come GarageBand
Cmd+K) o usare scorciatoie con modificatori.

## 8.3 Scorciatoie da tastiera — `MVP` (base), difficoltà bassa

Convenzioni comuni tra DAW (Ableton, FL Studio, Logic, BandLab):

| Azione | Scorciatoia |
|---|---|
| Play / Stop | Spazio |
| Annulla / Ripeti | Ctrl+Z / Ctrl+Shift+Z (o Ctrl+Y) |
| Copia / Incolla / Duplica | Ctrl+C / Ctrl+V / Ctrl+D |
| Elimina selezione | Canc / Backspace |
| Seleziona tutto | Ctrl+A |
| Salva | Ctrl+S |
| Loop on/off | L (Ableton usa Ctrl+L) |
| Metronomo | da decidere (non c'è uno standard unico tra DAW) |
| Registra | R (`v2`) |
| Zoom | Ctrl + rotella / + e - |
| Mute / Solo traccia selezionata | M / S (`v2`, conflitto con tastiera musicale) |

Scorciatoie in un unico modulo (`src/ui/shortcuts.ts`) con mappa azione → tasto, così si può mostrare
una schermata "Scorciatoie" (tasto `?`) e in futuro renderle personalizzabili (`nice`).

## 8.4 Preset — `MVP`, difficoltà bassa

- Preset per strumenti, kit di batteria ed effetti, raggruppati per categoria ("Bassi", "Tastiere", "Pad",
  "Lead") con un pulsante "ascolta anteprima".
- Salvataggio di preset personali (JSON in IndexedDB) — `v2`.
- "Randomizza" suono (genera parametri casuali sensati) — `nice`, divertente per chi esplora.

## 8.5 Onboarding per principianti — `MVP` (base) / `v2`

- **Schermata iniziale con template** (`MVP`): "Beat hip-hop", "House", "Lo-fi", "Vuoto" — progetti già con
  tracce, strumenti e un pattern d'esempio. GarageBand e BandLab partono così.
- **Tooltip su ogni controllo** (`MVP`) con spiegazione in parole semplici (riusare i testi di questi report:
  es. "Attack: quanto ci mette la nota a raggiungere il volume massimo").
- **Glossario** consultabile (`v2`).
- **Tutorial guidato** passo-passo "Il tuo primo beat in 5 minuti" (`v2`). Ottimo modello: Ableton
  "Learning Music" e "Learning Synths" (lezioni interattive nel browser).
- **Modalità semplice / avanzata** (`v2`): nascondere parametri avanzati (rolloff filtro, Q, knee…).
- Valori di default sensati ovunque e **limiter sul master** per evitare suoni troppo forti/distorti.

## 8.6 Controlli UI (manopole, fader) — `MVP`, difficoltà media

- Manopole: trascinamento verticale (standard DAW), Shift = regolazione fine, doppio click = valore di default,
  rotella del mouse, valore e unità visibili (Hz, dB, ms, %).
- Mappare correttamente le scale: frequenze e tempi su scala **logaritmica** (da 20 Hz a 20 kHz la metà
  della manopola deve essere ~600 Hz, non 10 kHz); volumi in dB.
- Accessibilità: controlli raggiungibili da tastiera, `aria-label`, contrasti adeguati (`v2`).

## 8.7 Feedback visivo — `MVP`

- Playhead che scorre, step attivo illuminato nello step sequencer, tasti della tastiera virtuale che si
  illuminano, meter che si muovono: rendono comprensibile "cosa sta succedendo".
- Sincronizzare la grafica all'audio con `Tone.getDraw().schedule(cb, time)` invece di `setTimeout`.

## 8.8 Affidabilità e prestazioni — `MVP`

- Pulsante/overlay "Clicca per attivare l'audio" (`await Tone.start()`), richiesto dai browser.
- Indicatore di carico CPU / avviso se l'audio "scatta" (`nice`; Web Audio non espone una vera misura di CPU).
- Browser consigliato: Chrome/Edge (supporto più completo di Web MIDI e File System Access). → Decisione aperta.
- Gestire `dispose()` di strumenti/effetti rimossi per non accumulare memoria.

## 8.9 Altre idee — `nice`

- Temi chiaro/scuro; lingua italiana/inglese dell'interfaccia.
- "MIDI learn": collegare una manopola fisica di un controller MIDI a un parametro.
- Visualizzazione "a colori per nota" per chi non legge la musica.
- Generatore di idee (melodia/accordi casuali in scala) per superare il "foglio bianco".
